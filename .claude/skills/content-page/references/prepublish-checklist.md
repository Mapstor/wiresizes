# Phase 4 — pre-publish gate

Every line, every page, before it ships. A failure is surfaced and fixed —
never shipped around. ■ = hard gate, □ = fix-or-justify.

## Truth & sourcing

- ■ Every number/fact traces to the data-sourcing registry or a verified
  primary; attributions rendered from registry strings.
- ■ Every attribution deep link resolves to a page showing the claim (click
  each one). No 404s, no homepage links.
- ■ Hook stat verified — or the hook carries no number.
- ■ Gaps disclosed in the methodology block; coverage limits stated where
  partial.
- ■ Derived values show/link their methodology; labeled as calculated.
- ■ Data-as-of stamp present and true; dateModified honest.

## Structure & content

- ■ Intro follows the formula for the archetype; ≤3 paragraphs before the
  answer block; zero throat-clearing.
- ■ 40–60-word direct-answer block present, key phrase bolded.
- ■ H2s match the deep-dive demand order; fan-out set covered; tertiary
  phrasings placed.
- ■ The named wedge is on the page and visible.
- ■ FAQ present, demand-ordered, answers self-contained.
- ■ Use-case section present where the page has (or links) a tool/map.
- ■ Length floor met WITHOUT padding — if it reads stretched, cut.
- □ Mini-tool considered where an interactive element serves the intent.

## Formatting

- ■ No paragraph over 4 sentences. Bold layer tells the story alone;
  no over-bolding.
- ■ 1–2 stat callouts with in-box attribution.
- ■ TOC with jump links if >~1,500 words.
- ■ Every unit dual: imperial primary, metric parenthetical, conversions
  correct.
- ■ No naked numbers anywhere — context pattern applied (meaning, relation,
  action).

## Visuals

- ■ Exactly ≥2 purpose-built SVGs (hero conceptual + supporting); charts
  additional; all pass the collision QA checklist (rendered and checked).
- ■ Hero flagged for Marko's spot-check queue.
- ■ Explicit dimensions on every visual (CLS); below-fold lazy-loaded.
- ■ OG image distinct, data-bearing, legible at thumbnail size.

## Tool pages

- ■ Tool above the fold; button-gated results; results panel extensive
  (chart + every number explained + assumptions + next steps).
- ■ Crawlable twin present: worked example + typical-values table +
  how-to-read-results prose.
- ■ JS-off test passes: view-source contains the data story.

## Links

- ■ 3–8 inline contextual anchors from the ledger plan; anchors to keywords
  owned elsewhere point at their owning pages.
- ■ Hub link present; one related block at end; no orphan on ship — the
  reverse-link injection list (which existing pages link in, with which
  anchors) is written and applied.

## Technical & compliance

- ■ Schema per seo-visibility's supported list, validated, matching visible
  content; no aggregateRating, no reliance on FAQ/HowTo rich results.
- ■ Mobile: zero horizontal overflow at 360 px; tables in contained
  scrollers; tap targets sane.
- ■ CWV sanity: hero not tanking LCP; heavy JS deferred (INP).
- ■ google-ai-content-policy check on the page in its cluster context — no
  doorway pattern, no template-flat siblings.
- ■ YMYL-adjacent: author credential + disclosure block present.
- ■ Real-name author + Person schema; reviewed date.

Gate passed → ship with the reverse-link list. Gate failed → fix, re-run,
then ship.
